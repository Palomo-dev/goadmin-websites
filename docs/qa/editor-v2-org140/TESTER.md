# Evidencia del editor y la tienda: org 140

Esta evidencia cubre render local e interacciones aisladas. **No confirma un despliegue, la tienda en vivo ni una sesión autenticada del editor.** La entrega permanece pendiente de esas comprobaciones.

[Galería de PNG antes/después](GALLERY.md) · [Galería HTML descargable](index.html) · [Reporte de capturas](capture-report.json) · [Reporte de interacciones](interaction-report.json)

## Método y resultados

- Antes: `goadmin-websites` `origin/main`, commit `77176316af25f2b1fba465b472bb09b3cfa32175`.
- Después: árbol de trabajo sobre `5f2e57d65e2b7c4caf020d4aba5cb5ecc0be28fb`, con las correcciones de integración descritas en [la procedencia de esta ronda](round.json). La base de ese commit es `7717631`. La comparativa anterior se conserva fuera del repositorio y no se presenta como evidencia de este árbol actualizado.
- 184 capturas: 46 escenarios × antes/después × escritorio de 1440 px y celular de 390 px. No se detectaron desbordamientos horizontales ni bloques colapsados. Cargaron las 88 imágenes presentes en esos renders.
- 4 capturas adicionales de interacciones móviles. Pasaron 8 comprobaciones: abrir y cerrar el menú superior y los laterales izquierdo/derecho; ejecutar el callback de «Pedir» sin navegar; cerrar el diálogo de prueba.
- El agente principal verificó los scripts versionados de tarjeta (186 comprobaciones), selector de opciones (22 comprobaciones DOM, móvil/escritorio) y encabezado (147 comprobaciones), además de las 8 interacciones de navegador. El tester revisó los reportes, la procedencia y las capturas de esta ronda. No se presenta el conteo de una ronda anterior como verificación posterior al rebase.
- Se revisaron visualmente cinco capturas representativas de esta ronda: bloque base de producto en celular, distribución de banners en escritorio, mosaico de categorías en celular, buscador en escritorio y callback de «Pedir» en celular. La recaptura final posterior a la corrección del enlace como hijo directo de grid muestra el banner grande y los dos pequeños apilados en sus posiciones correctas.

Los productos, precios, categorías y fotos provienen de un snapshot público de org 140, obtenido mediante MCP después de validar el esquema. No se publica ese documento completo. Se armaron configuraciones de demostración para activar las opciones nuevas: **reseñas 4.7/12, stock de 3 unidades y una oferta a una hora son datos de demostración**; no son afirmaciones sobre ventas, existencias u ofertas vigentes.

La comparación usa el mismo contenido y opciones en ambos árboles. `main` ya contiene varias capacidades; algunas imágenes antes/después pueden ser iguales, y no se alteraron para aparentar una diferencia. Los buscadores, contenedores y menús se renderizan con sus implementaciones reales en ambas versiones. Las capturas usan SSR de componentes reales y CSS compilado por separado desde cada versión. En el caso del bloque base se renderizaron `ProductDetailRenderer`, `CategoryDetailRenderer`, `SectionRenderer` y sus subcomponentes reales. Se simularon dependencias de infraestructura, como navegación de Next, moneda, favoritos y acciones externas. Las imágenes públicas se almacenaron temporalmente fuera del repositorio para capturarlas sin fallos de red. No se copiaron esos archivos, el snapshot, credenciales, perfiles del navegador ni scripts del entorno a este directorio.

Las interacciones usan React real con `MobileMenuShell` y `MobileBottomNav`. El callback de carrito se representa con un diálogo de prueba: **no es el carrito completo ni prueba checkout, pagos o pedidos**. El primer intento de «Pedir» falló por un fixture de dos ítems: el parser exige tres y activó la barra predeterminada; el selector había pulsado «Buscar». Se corrigió el fixture a tres ítems y se añadió una aserción de la etiqueta «Pedir» antes del clic. La ejecución corregida pasó las ocho comprobaciones.

## Verificación reproducible de esta ronda

Los siguientes scripts están versionados en `goadmin-websites` y fueron verificados por el agente principal en la integración. Usan dependencias simuladas donde sus fuentes lo indican. El conteo de aserciones SSR/DOM no equivale a sesiones de navegador ni confirma el despliegue.

| Comando | Resultado de la ronda |
| --- | --- |
| `node scripts/verify-product-card-render.cjs` | 186 comprobaciones de render correctas |
| `node scripts/verify-product-choice-interaction.cjs` | 22 comprobaciones DOM correctas con selectores reales en móvil/escritorio |
| `node scripts/verify-header-render.cjs` | 147 comprobaciones de encabezado/búsqueda correctas |

El [reporte de interacciones](interaction-report.json) registra ocho comprobaciones de navegador correctas y cuatro PNG adicionales. El agente principal también verificó typecheck del ERP y de la tienda, build de la tienda y 925 pruebas del ERP; esta galería no amplía ese resultado a una sesión autenticada o despliegue. Las demás suites citadas en la matriz son fuentes de regresión versionadas; no se adjudica aquí un conteo nuevo a partir de ejecuciones anteriores al rebase. Una verificación temporal suplementaria de accesibilidad no se presenta como suite estable.

No se ejecutó un pedido, un pago ni una publicación real como parte de esta evidencia. No se asigna aprobación al alcance completo mientras falte el recorrido autenticado y desplegado.
